# Galactic Bridge

**Мова:** Українська · [English](README_ENG.md)

Універсальний інтерфейс для міжмережевих переказів токенів **LayerZero V2 OFT**.

Переносить будь-який OFT-токен між EVM-мережами — зокрема ті, яких немає в
Stargate чи інших мостах. Ви вводите адресу контракту токена, а міст сам
знаходить OFT-контракт, маршрут, комісію і збирає транзакцію.

Працює на **https://galacticbridge.app** — або запустіть локально за інструкцією нижче.

📖 **Повна документація:** https://galactic-bridge.gitbook.io/galactic-bridge-docs/ (англійською)

---

## Навіщо це

Більшість мостів підтримують лише ті токени, які команда додала вручну. Якщо
проєкт так і не потрапив у список, переносити токен доводиться самотужки: шукати
OFT-контракт у провіднику блоків, розбирати чужу транзакцію бріджа і збирати
виклик руками. Довго й легко помилитися.

Galactic Bridge робить це за вас.

## Можливості

- **Працює з будь-яким OFT-токеном** — без списків дозволених, без ручних налаштувань.
- **Сам знаходить контракт бріджа**, зокрема окремий *адаптер* для токенів,
  які самі не є OFT.
- **Маршрути без історії** — питає контракт напряму, з якими мережами він
  зʼєднаний, тому маршрут працює навіть якщо ним ще ніхто не користувався.
- **Сам будує транзакцію, коли копіювати нема з чого.** Зазвичай формат виклику
  зчитується з реальної прямої транзакції контракту — багато OFT мають
  нестандартні селектори, тож формат надійніше визначити, ніж припустити. Але
  популярні токени зазвичай бріджать через роутери й агрегатори, і в такій
  транзакції лежить calldata роутера, а не самого токена. Якщо прямого прикладу
  немає, виклик збирається за стандартним інтерфейсом LayerZero V2. Комісія в
  обох випадках береться живим запитом `quoteSend()`.
- **Некастодіальний** — інтерфейс не зберігає ні коштів, ні ключів. Кожну
  транзакцію ви підписуєте у своєму гаманці. Без реєстрації та особистих даних.
- **Збережені токени** — часто вживані токени можна зберегти й викликати за
  тікером. Зберігаються лише у вашому браузері, не на сервері.
- **13 мереж:** Ethereum, BNB Chain, Base, Arbitrum, Optimism, Polygon,
  Avalanche, Mantle, HyperEVM, Ink, X Layer, Plasma, Robinhood.

## Швидкий запуск (Windows)

1. Встановіть [Node.js LTS](https://nodejs.org/).
2. Завантажте або клонуйте цей репозиторій.
3. Двічі клацніть **`start.bat`**.

При першому запуску створиться файл `.env` і встановляться залежності. Коли
вікно frontend буде готове, відкрийте `http://localhost:5173`.

## Швидкий запуск (macOS / Linux)

```bash
git clone https://github.com/<ваш-нік>/galactic-bridge.git
cd galactic-bridge
cp .env.example .env          # далі відредагуйте .env, див. «Налаштування»

cd backend  && npm install && cd ..
cd frontend && npm install && cd ..

grep '^VITE_' .env > frontend/.env

# термінал 1
cd backend && node server.js

# термінал 2
cd frontend && npm run dev
```

Відкрийте `http://localhost:5173`.

## Налаштування

Скопіюйте `.env.example` у `.env` і заповніть.

| Змінна | Обовʼязкова | Призначення |
|---|---|---|
| `VITE_REOWN_PROJECT_ID` | **Так** | Підключення гаманця. Отримайте **власний** безкоштовний ID на [dashboard.reown.com](https://dashboard.reown.com) — він привʼязаний до акаунта і має свої ліміти, тому чужий використовувати не можна. Без нього вікно вибору гаманця буде порожнім. |
| `VITE_CF_BEACON_TOKEN` | Ні | Токен веб-аналітики Cloudflare — лише якщо ви хостите власний сайт. Порожньо = скрипт аналітики не підключається взагалі. |
| `PORT` | Ні | Порт backend. За замовчуванням `3001`. |
| `ALLOWED_ORIGINS` | Ні | Дозволені домени (CORS), через кому. Порожньо = відкрито (для розробки). У проді задавайте обовʼязково. |
| `RL_MAX`, `RL_WINDOW_MS` | Ні | Обмеження запитів на IP. За замовчуванням 60 за 15 с. |
| `LOGS_RPC_<МЕРЕЖА>` | Ні | Архівний RPC для конкретної мережі, напр. `LOGS_RPC_BSC`. Див. нижче. |

> `frontend/.env` формується з рядків `VITE_` кореневого `.env`.
> `start.bat` робить це сам; на macOS/Linux виконайте команду `grep` вище.

### Про `LOGS_RPC_<МЕРЕЖА>`

Щоб знайти адаптер для токена, який сам не є OFT, потрібно читати історичні логи
подій. Частина публічних вузлів не дозволяє `eth_getLogs` або віддає лише
найсвіжіші блоки. У такому разі вкажіть вузол з архівним доступом:

```
LOGS_RPC_BSC=https://bsc-mainnet.nodereal.io/v1/ВАШ_КЛЮЧ
```

Безкоштовних тарифів [NodeReal](https://nodereal.io), [Ankr](https://www.ankr.com/rpc/),
[dRPC](https://drpc.org) чи [Alchemy](https://alchemy.com) вистачає із запасом.
Ключі мереж: `eth`, `bsc`, `base`, `arb`, `poly`, `op`, `avax`, `mantle`,
`hyperevm`, `ink`, `xlayer`, `plasma`, `robinhood`.

Перевірити всі мережі одразу:

```bash
cd backend && node tools/checkLogsRpc.js
```

## Як це працює

**1. Визначення OFT-контракту.**
Спершу міст питає API LayerZero, чи є сама адреса токена OFT-контрактом. Якщо ні —
токен використовує окремий *адаптер*. Щоб його знайти, міст бере логи `Transfer`
токена і події LayerZero `OFTSent`/`OFTReceived` за той самий діапазон блоків і
перетинає їх за хешем транзакції. Збіг одразу вказує на адаптер — без перебору
кожної транзакції. Кандидат перевіряється викликом `token()`, тому транзакція
агрегатора, де свопиться кілька токенів, не дасть хибного результату.

**2. Визначення маршруту.** По черзі:

1. **Пряме** — шукаємо доставлене повідомлення LayerZero саме в цьому напрямку.
2. **Зворотне** — якщо відомий контракт призначення, шукаємо з його боку.
3. **`peers()`** — питаємо вихідний контракт, з якою адресою він зʼєднаний у
   мережі призначення. Це стандартна функція LayerZero V2, тому маршрут
   підтверджується навіть за нульової історії. Знаючи контракт призначення,
   зворотний пошук повторюється і дає реальні транзакції.
4. Якщо нічого не спрацювало — користувач може ввести контракт або хеш
   транзакції-прикладу вручну.

**3. Побудова транзакції.** По черзі:

1. **Копіюємо формат** із реальної *прямої* транзакції того самого контракту.
   Транзакції через роутери пропускаються навмисно — там calldata роутера.
   Багато OFT мають нестандартні селектори, тож визначений формат надійніший
   за припущений.
2. **Збираємо за стандартом**, якщо прямого прикладу немає. Успішна відповідь
   на `quoteSend()` доводить, що контракт реалізує інтерфейс LayerZero V2 OFT,
   отже виклик можна побудувати з нуля.

В обох випадках комісія береться живим викликом `quoteSend()` для потрібної
мережі; комісія з прикладу — лише запасний варіант.

**4. Пошук мереж токена.**
При збереженні токена міст обходить усі повʼязані контракти через `peers()` і
доповнює результат історією LayerZero. Мережі не завжди зʼєднані «зіркою», тому
опитується кожен вузол, а не лише початковий.

## Що підтримується, а що ні

LayerZero Scan показує **усі** застосунки на LayerZero, і більшість із них —
взагалі не перекази токенів. Ця різниця економить багато здогадок.

| Тип | Підтримка | Чому |
|---|---|---|
| **LayerZero V2 OFT** | ✅ | Стандарт, під який зроблено міст. |
| V2 OFT через роутери | ✅ | Виклик збирається за стандартом, а не копіюється. |
| V2 OFT з окремим адаптером | ✅ * | Адаптер знаходиться автоматично — якщо RPC мережі віддає історичні логи. |
| **LayerZero V1** | ❌ | Інший протокол: інший ендпоінт, інша функція, інші ідентифікатори мереж. Розпізнається й повідомляється явно. |
| Власні V2 OApp | ❌ | Мають `peers()`, але не мають `token()` / `quoteSend()` — у кожного свій самописний інтерфейс. |
| Пули Stargate (USDC тощо) | ❌ | Власна архітектура пулів, не стандарт OFT. Користуйтесь інтерфейсом Stargate. |

**Перевірити токен за 5 секунд** — чи це взагалі OFT:

```
https://scan.layerzero-api.com/v1/messages/oapp/<EID>/<АДРЕСА_ТОКЕНА>?limit=1
```

Прийшов список повідомлень — так. `{"code":4040}` — адреса не є OApp у цій
мережі, отже потрібен адаптер або це не OFT.

EID: Ethereum `30101`, BNB Chain `30102`, Avalanche `30106`, Polygon `30109`,
Arbitrum `30110`, Optimism `30111`, Mantle `30181`, Base `30184`,
X Layer `30274`, Ink `30339`, HyperEVM `30367`, Plasma `30383`,
Robinhood `30416`.

> Беріть EID тієї мережі, якій належить адреса. Той самий токен в одній мережі
> може бути звичайним OFT, а в іншій — працювати через адаптер.

### Чому публічного RPC іноді не досить

Щоб знайти адаптер, треба читати історичні логи подій, а безкоштовні публічні
вузли поводяться дуже по-різному:

- одні взагалі не дають `eth_getLogs` (`limit exceeded`);
- інші віддають лише кілька тисяч найсвіжіших блоків (потрібен архівний доступ);
- треті обмежують діапазон 100–500 блоками, чого для сканування замало;
- деякі не тримають індекс старих транзакцій і повертають `null`.

Міст чергує вузли й **ніколи не тлумачить помилку RPC як «даних немає»**. Якщо
для мережі не працює жоден безкоштовний вузол — вкажіть архівний через
`LOGS_RPC_<МЕРЕЖА>`; безкоштовного тарифу NodeReal, Ankr, dRPC чи Alchemy
вистачає. Стан усіх мереж покаже `node backend/tools/checkLogsRpc.js`.

## Структура проєкту

```
backend/
  server.js              Express, список дозволених доменів, обмеження запитів
  lib/
    chains.js            Опис мереж (RPC, EID, провідник)
    oftSearch.js         Ядро: пошук OFT, маршрутів, peers()
    decoder.js           Розбір формату виклику з реальної транзакції
    rpc.js               Робота з JSON-RPC + повторні спроби
    explorer.js          Адреси API LayerZero
  routes/                find-params, scan-token, balance, quote, tx-status
  tools/
    checkLogsRpc.js      Діагностика: чи віддає кожна мережа глибокі логи
    findRpc.js           Підбір робочого RPC зі списку кандидатів
frontend/
  src/
    App.jsx              Основний інтерфейс і логіка бріджа
    main.jsx             Налаштування wagmi + Reown AppKit
    lib/                 Мережі, кодування, форматування
    components/          Вікно токенів, вікно рідкісного маршруту, футер
```

## Як додати мережу

Додайте запис до обʼєкта `CHAINS` **в обох** файлах — `backend/lib/chains.js` і
`frontend/src/lib/chains.js`, потім зареєструйте мережу для гаманця у
`frontend/src/main.jsx`. Ідентифікатор `eid` беріть з
[документації LayerZero](https://docs.layerzero.network/v2/deployments/deployed-contracts) —
він **не** збігається з chain ID.

## Усунення несправностей

**Вікно гаманця порожнє** — не заданий `VITE_REOWN_PROJECT_ID`. Впишіть його в
`.env`, перестворіть `frontend/.env` і перезапустіть dev-сервер (Vite читає
змінні лише при старті).

**«Bridge route not found»** — можливо, маршрутом справді ще не користувалися.
Спробуйте ввести контракт призначення або хеш транзакції вручну.

**Пошук токена нічого не знаходить** — найчастіше RPC мережі не віддає історичні
логи. Запустіть `node backend/tools/checkLogsRpc.js` і за потреби задайте
`LOGS_RPC_<МЕРЕЖА>`.

**Баланс показує `—`** — перевірте, що гаманець підключений, токен існує у
вибраній вихідній мережі, а RPC доступний.

## Про безпеку

- Інтерфейс некастодіальний і **ніколи** не просить приватний ключ чи seed-фразу.
- На сервері нічого не зберігається: збережені токени лежать у локальному
  сховищі вашого браузера.
- **Завжди перевіряйте адресу контракту, яку вставляєте.** Будь-хто може
  випустити токен зі знайомою назвою чи тікером. Міст не перевіряє і не
  рекомендує жодного токена.
- Ніколи не додавайте свій `.env` у git — він не дарма в `.gitignore`.

## Відмова від відповідальності

Надається «як є», без жодних гарантій. Криптовалютні транзакції незворотні.
Перевіряйте мережу призначення та суму перед підтвердженням. Використовуєте на
власний ризик. Це не є фінансовою порадою.
